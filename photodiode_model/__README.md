## Module Responsibilities

### `constants.py`
Universal physical constants. Never parametrised, never imported with `*`.
```python
q    = 1.602176634e-19   # C
kB   = 1.380649e-23      # J/K
eps0 = 8.854187817e-12   # F/m
```

### `materials/`
Split from constants because material parameters are per-material, not universal,
and some (ni, mobility) are temperature-dependent.

```python
@dataclass
class Material:
    eps_r: float
    def ni(self, T: float) -> float: ...      # intrinsic carrier density [m^-3]
    def mu_n(self, T: float) -> float: ...    # electron mobility [m^2/Vs]
    def mu_p(self, T: float) -> float: ...    # hole mobility [m^2/Vs]

class Silicon(Material):
    eps_r = 11.7
    def ni(self, T): ...   # Varshni or tabulated fit
```

### `device.py`
Defines what the device **is**. No solver logic. No mesh. No computed fields.
Validation in `__post_init__` catches bad inputs at construction time.

```python
@dataclass
class Device:
    material: Material
    NA: float          # m^-3
    ND: float          # m^-3
    Lp: float          # m — total p-side length
    Ln: float          # m — total n-side length
    Va: float = 0.0    # V — applied bias (+ forward, - reverse)
    T:  float = 300.0  # K

    def __post_init__(self):
        # Unit guard: doping below ~1e18 m^-3 almost certainly means cm^-3 was passed
        if self.NA < 1e18 or self.ND < 1e18:
            raise ValueError("Doping looks like cm^-3 — expected m^-3. Multiply by 1e6.")
        if self.Lp <= 0 or self.Ln <= 0:
            raise ValueError("Device lengths must be positive.")
        if self.T <= 0:
            raise ValueError("Temperature must be positive.")

    def make_mesh(self, Nz: int = 20000) -> np.ndarray:
        # Mesh construction belongs here: it's based on device geometry,
        # is always uniform for now, and Nz is a solver-level numerical choice.
        return np.linspace(-self.Lp, self.Ln, Nz)
```

> **On the mesh**: `make_mesh` lives on `Device` because the extent
> `[-Lp, Ln]` is a physical property. `Nz` is passed in because it is a
> numerical choice, not a device property. If non-uniform meshing is needed
> later, add a second method or promote to a `Mesh` class at that point.

### `physics/depletion.py`
Computes depletion-approximation quantities. Returns a result object — does not
modify `Device`. Validates physical constraints before integrating.

Responsibilities: `Vbi`, `Vtotal`, `W`, `xp`, `xn`, `rho(z)`.
Does **not** compute `E` or `V` — that is Poisson's job.

```python
class DepletionApproximation:
    def __init__(self, device: Device): ...

    def solve(self) -> DepletionResult:
        # Guard: forward bias exceeding Vbi is unphysical
        if Vtotal <= 0:
            raise ValueError(...)
        # Guard: depletion region wider than device
        if W >= device.Lp or W >= device.Ln:
            raise ValueError(...)
        ...
```

### `physics/poisson.py`
Integrates `rho(z)` → `E(z)` → `V(z)` using `cumulative_trapezoid`.
Agnostic to how `rho` was computed — accepts any charge density array.
This decoupling is essential: the Gummel solver will update `rho`
self-consistently and re-call `PoissonSolver` in a loop.

### `results.py`
Bundle outputs into a named structure. Minimum viable version is a `NamedTuple`.
The rule: **never return multiple bare arrays from a solver**.
`return z, rho, E, V` means callers write `_, _, E, _ = solve(...)` and
provenance is lost. A named result carries its own context.

```python
from typing import NamedTuple

class SimulationResult(NamedTuple):
    z:      np.ndarray    # m
    rho:    np.ndarray    # C/m^3
    E:      np.ndarray    # V/m
    V:      np.ndarray    # V
    device: Device        # inputs that produced this result
```

> Upgrade to a full `@dataclass` when you need serialisation or
> metadata (solver type, convergence info, timestamp).

## Testing

### Principle
- **pytest**: correctness — does the physics give the right answer?
- **in-code validation**: misuse — was the function called correctly?

Do not put physics checks (charge neutrality, Poisson consistency) inside
the solver. They are test concerns, not runtime concerns.

### `conftest.py` — single source of fixtures
Change a fixture here and every test that uses it re-runs against the new
implementation. This is what makes refactoring safe.

```python
@pytest.fixture
def silicon():
    return Silicon(T=300.0)

@pytest.fixture
def asymmetric_device(silicon):
    return Device(material=silicon, NA=1e23, ND=1e22, Lp=500e-9, Ln=500e-9)

@pytest.fixture
def symmetric_device(silicon):
    return Device(material=silicon, NA=1e22, ND=1e22, Lp=500e-9, Ln=500e-9)

@pytest.fixture
def depletion_result(asymmetric_device):
    return DepletionApproximation(asymmetric_device).solve()

@pytest.fixture
def sim_result(asymmetric_device):
    return run_full_simulation(asymmetric_device)
```

### Required tests — priority order

| Test | What it catches |
|---|---|
| `NA * xp == ND * xn` | Algebra error in depletion widths |
| `xp + xn == W` | Inconsistent width calculation |
| `V(+Ln) == Vbi` | Unit error, wrong sign in integration |
| `E(-Lp) == E(+Ln) == 0` | Boundary condition failure |
| `integral(rho dz) == 0` | Charge density construction error |
| `d(E)/dz == rho/eps_s` | Poisson round-trip consistency |
| `W scales as sqrt(Vtotal)` | Wrong functional form |
| Symmetric junction: `xp == xn`, `E` antisymmetric | Sign convention errors |
| Regression: freeze known-good output values | Silent breakage from refactoring |

### Refactoring workflow
1. Make the code change
2. Update the affected fixture(s) in `conftest.py`
3. Run `pytest` — failures are localised to what actually broke
4. Fix, re-run, commit

## Key Rules

**Separation of concerns**
- `Device` knows geometry and doping. Not how to solve Poisson.
- `DepletionApproximation` knows the depletion model. Not the mesh.
- `PoissonSolver` knows numerical integration. Not what produced `rho`.

**Derived quantities are not device properties**
`Vbi`, `W`, `xp`, `xn` are outputs of a computation, not properties of the
device. They live on solver result objects, not on `Device`.

**Units are always SI (m, V, C, F/m)**
Convert at input/output boundaries only. Every variable comment states the unit.
The `Device.__post_init__` unit guard is the most important single validation.

**Gummel iteration fits the architecture without changes**
The Gummel loop is: initialise `rho` from depletion → solve Poisson → solve
continuity equations → update `rho` → repeat. `PoissonSolver` is unchanged;
only the `rho` source changes. This is why `DepletionApproximation` and
`PoissonSolver` are separate.

**Compact model / parameter fitting**
`Device` is a plain dataclass — copy it, perturb a field, pass the copy to the
solver. `scipy.optimize` or a Bayesian sampler drives the outer loop.
`experiment/loader.py` provides the target data. No solver internals need to
change.
